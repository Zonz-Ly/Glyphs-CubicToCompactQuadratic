## 正確性

普通擬合的預設驗證精度改為 `min(max(.002, tolerance*.02), tolerance*.1)`，與合併和居中一致；快取鍵仍包含曲線與精度。審查的 `1e-5` 容差案例現在可通過，未放寬容差。

分割器先最小化區塊數及最大合併誤差，再以所得誤差為門檻，最小化區塊數及控制點總數。保留全部區間及封閉鏈旋轉起點，未以短區間失敗推斷長區間也會失敗。審查反例由 `(3, .5, 5)` 修正為 `(3, .5, 3)`；另以 120 組合成開放／封閉鏈逐一與窮舉成本比較。這證明成本遞推，不代表同樣成本已出現在真實字型中。

單控制點先檢查兩條精確浮點射線是否有唯一可行交點；整數模式仍按射線穿過格點方格的規則處理，平行射線保留既有搜尋。

簡單候選沿用 L2 控制點，套用所需切線、整數搜尋及居中後，使用 `|D|/(12 sqrt(3)) + |Q'-Q|/2 + allowance` 作雙向 Hausdorff 上界。證明失敗或便宜格點候選不可行，仍回到原搜尋。所有接受都保留誤差保證；此路徑不保證與原先完整 RMS 搜尋選到相同控制點。切線唯一交點路徑仍用原連續誤差驗證器，以保持其回傳界限一致。

## 同機小型測速

macOS 14.8.7 arm64，Apple Command Line Tools CPython 3.9.6。基準與最終版本在同一台機器依次執行，不與測試並行；每案 5 或 7 次取中位數。擬合案例每次清除數值與係數快取；投影批次重用每條曲線的不變係數，長鏈投影不含 Context 建立時間。最終算法版本為 `d383a23`。

| 案例 | 原版 ms | 最終 ms | 倍率 | 完整回傳值一致 |
| --- | ---: | ---: | ---: | --- |
| 1,950 次最近二次曲線查詢 | 14.273 | 13.522 | 1.06 | 是 |
| 對稱曲線／單控制點 | 103.155 | 59.364 | 1.74 | 是 |
| 唯一切線交點／浮點 | 83.455 | 13.613 | 6.13 | 是 |
| 便宜候選／浮點 | 88.587 | 0.010 | 8896.06 | 否；控制點不同，容差內提早接受 |
| 便宜候選／整數 | 91.906 | 15.719 | 5.85 | 否；控制點一致，誤差界限不同 |
| 對應曲線／最多三控制點／整數 | 557.226 | 523.414 | 1.06 | 是 |
| 三段擬合誤差驗證 | 22.184 | 20.032 | 1.11 | 是 |
| 32 段來源鏈／100 次投影 | 6.350 | 5.576 | 1.14 | 是 |

浮點簡單候選只需直接證明，因此極短測時與極大倍率只適用於該合成案例，不能當作整體外掛加速。32 段測試亦不代表所有字型曲線鏈；AABB 的大量重疊情況仍可能需要訪問大部分曲線。

`redundancy-benchmark.json` 在加入簡單候選前的 `73c9faf` 執行：八組案例的完整回傳值均與基準相同。最終版本六組仍完全相同；浮點簡單候選改變控制點，整數簡單候選的控制點相同、僅回傳誤差界限不同，兩組都有獨立連續誤差檢查。原始測時與完整輸出在三份 `*-benchmark.json`，彙總見 `comparison.json`。

兩組簡單候選的容差均為 `0.5`。「完整回傳值一致」包含 `parts`、`error` 和 `single_error` 等欄位，並非只比較曲線幾何：

- 浮點：控制點由約 `(50.001014, 99.776218)` 改為 L2 候選 `(49.625, 99.75)`；回傳誤差上界由 `0.021996` 改為便宜證明的 `0.146329`。用同一連續驗證器重算，原版區間為 `[0.012522, 0.021996]`，新版為 `[0.114332, 0.123811]`。這個案例確實以部分擬合精度換取速度，仍符合容差。
- 整數：前後控制點都是 `(50, 100)`，曲線完全相同。舊版連續驗證回傳 `[0.122796, 0.132271]`，新版便宜證明回傳 `[0, 0.371675]`。新版界限較鬆；曲線的實際誤差沒有增加，用同一連續驗證器重算仍得到原區間。`error` 與 `single_error` 的不同使完整回傳值比較為「否」。

這兩項的加速來自先證明已達容差，省去完整無約束最佳化；整數模式仍執行格點調整。上界不是精確最大誤差，較大的保守上界亦可能影響上層依誤差界限進行的候選比較。

`baseline-review-probes.json` 是在原始碼匯出副本上執行提供的 `review_probes.py` 得到的結果。原腳本刻意斷言原版分割成本比窮舉差，且用原函式原始碼生成原型，所以修正後應運行新增回歸測試，不應繼續要求原腳本的反例斷言成立。

## 重跑

在項目根目錄：

```sh
python3 build.py
python3 -m unittest discover -s development -q
python3 development/benchmark_review.py --output /tmp/cubic-final-benchmark.json
```

比較原始碼匯出副本時，可用 `--repo /path/to/export --revision <commit>`。基準版本的完整測試需同樣放入發布包外掛並重建引擎。
